# Implementation Status

This document describes what has been implemented in the fissiondocs monorepo as of the initial scaffolding pass (July 2026).

---

## Repository Layout

```
fissiondocs/
├── apps/
│   ├── api/          Express.js API server (modular monolith)
│   ├── search/       Standalone OpenSearch query service
│   ├── web/          Next.js 15 frontend
│   └── worker/       SQS consumer (PDF scan + search indexer)
├── packages/
│   ├── config/       Zod env schemas, validated at startup
│   ├── db/           Drizzle ORM schema, migrations, RLS helpers
│   └── types/        Shared TypeScript types for all services
├── scripts/
│   └── localstack-init.sh   Creates S3 buckets and SQS queues on dev startup
└── docker-compose.yml       Local dev infrastructure
```

## packages/types

Shared TypeScript types consumed by all apps. No runtime code.

| File | Contents |
|------|----------|
| `entities.ts` | Interfaces: `Organization`, `User`, `Group`, `Space`, `Document`, `Attachment`, `AuditLogEntry`, etc. |
| `enums.ts` | String union types: `UserRole`, `UserStatus`, `AccessLevel`, `DocumentType`, `DocumentStatus`, `ScanStatus`, `AuditAction` |
| `api.ts` | Request bodies (`CreateDocumentBody`, `InviteUserBody`, …), response shapes (`SearchHit`, `SearchResponse`, `AuthTokenPayload`, `TenantContext`) |
| `queue.ts` | SQS message payloads: `PdfProcessingMessage`, `SearchIndexMessage` |
| `search.ts` | `SearchIndexDocument` — the shape written to and read from OpenSearch |

## packages/config

Zod-validated environment variable schemas. Each app calls its parser at startup; invalid env exits immediately with a clear error.

- `parseApiEnv()` — API server config (adds `API_PORT`)
- `parseSearchEnv()` — Search service config (adds `SEARCH_PORT`)
- `parseWorkerEnv()` — Worker config (same as base)

All schemas share a base that covers: `DATABASE_URL`, `REDIS_URL`, AWS credentials, S3 bucket names, SQS queue URLs, Cognito pool IDs, `BASE_DOMAIN`, `JWT_SECRET`, `SES_FROM_ADDRESS`.

| `space_permissions` | `spaceId`, `groupId`, `accessLevel` (view/edit) — composite PK |
| `documents` | `id`, `orgId`, `spaceId`, `parentId`, `type` (page/pdf), `title`, `contentRef`, `ownerId`, `status` (draft/published/trashed), `version`, `tags[]` |
| `document_permissions` | `documentId`, `groupId?`, `userId?`, `accessLevel` — per-document ACL overrides |
| `document_versions` | `documentId`, `versionNumber`, `contentSnapshot`, `editedBy`, `editedAt` |
| `attachments` | `id`, `orgId`, `documentId`, `quarantineKey`, `s3Key?`, `fileType`, `sizeBytes`, `scanStatus` |
| `audit_log` | `orgId`, `actorId`, `action`, `target` (jsonb), `ipAddress`, `timestamp` |
| `invite_tokens` | `orgId`, `userId`, `token` (unique), `expiresAt`, `usedAt?` |

### Row-Level Security (`src/rls.ts`)

RLS is enabled on all tenant tables. Every policy checks `current_setting('app.current_org_id', true)::uuid`. The API calls `SET LOCAL set_config(...)` (via `setTenantContext()`) at the start of each request, so a leaking `orgId` in application code cannot read another tenant's rows.

### Migrations

`src/migrations/0000_graceful_vivisector.sql` — initial full schema migration, generated by Drizzle Kit. Includes all FK constraints and indexes.

## apps/api

Express.js modular monolith. Entry point: `src/server.ts` → `src/app.ts`.

### Middleware stack (applied in order)

| Middleware | Purpose |
|------------|---------|
| `helmet` | Security headers |
| `cors` | Allows `*.BASE_DOMAIN` origins only; credentials included |
| `cookieParser` | Cookie support for future cookie-based auth |
| `express.json` | JSON body parsing, 2 MB limit |
| `requestId` | Attaches `x-request-id` to every request |
| `morgan` | HTTP access log via Winston |
| `auth` | Verifies Cognito JWT (RS256); in dev accepts HS256 with `JWT_SECRET` |
| `tenantContext` | Sets Postgres RLS context; loads user's group IDs (Redis-cached, 30 s TTL) |

### Domain routers

All routes live under `/api/`. Every route requires a valid JWT.

**Identity** (`domains/identity/router.ts`)
- `GET /users` — list org users
- `POST /users/invite` — create user + invite token (7-day expiry); admin only
- `PATCH /users/:userId/role` — change role; admin only; guards against removing the last admin
- `DELETE /users/:userId` — soft-deactivate; admin only

**Access** (`domains/access/router.ts`)
- `GET /groups` — list groups
- `POST /groups` — create group; admin only
- `DELETE /groups/:groupId` — delete group; admin only
- `POST /groups/:groupId/members` — add members; invalidates Redis ACL cache per user
- `DELETE /groups/:groupId/members/:userId` — remove member; invalidates Redis ACL cache

**Navigation / Spaces** (`domains/navigation/router.ts`)
- `GET /spaces` — list spaces visible to the caller (admins see all; others see spaces their groups have access to)
- `POST /spaces` — create space with group permissions; admin only
- `GET /spaces/:spaceId` — get single space (access-checked)
- `DELETE /spaces/:spaceId` — delete space; admin only

**Content / Documents** (`domains/content/router.ts`)
- `GET /spaces/:spaceId/documents` — list documents in a space
- `POST /documents` — create document; saves version 1; enqueues `SEARCH_INDEX` upsert
- `GET /documents/:documentId` — get document (document-level ACL → space-level fallback)
- `PATCH /documents/:documentId` — update title/content/tags/status; increments version; saves snapshot if content changed; enqueues `SEARCH_INDEX` upsert
- `DELETE /documents/:documentId` — soft-delete (sets `status = trashed`); enqueues `SEARCH_INDEX` delete
- `GET /documents/:documentId/versions` — list version history

**Storage / Attachments** (`domains/storage/router.ts`)
- `POST /documents/:documentId/attachments` — multipart upload (multer, in-memory); writes file to quarantine S3 bucket; inserts attachment record (`scanStatus: pending`); enqueues `PDF_PROCESSING` message
- `GET /attachments/:attachmentId/status` — poll scan status
- `GET /attachments/:attachmentId/view` — generate presigned URL (5-min TTL) for a clean attachment after verifying document-level read access

**Admin** (`domains/admin/router.ts`)
- `GET /admin/audit-log` — paginated audit log (max 200 rows); admin only
- `PATCH /admin/settings` — update org name, branding (logoUrl, primaryColor hex), maxFileSizeBytes (1 MB–500 MB), trashRetentionDays (1–365); admin only

### Permission resolver (`domains/access/permissionResolver.ts`)

`assertDocumentAccess` — checks document-level permission overrides first, then falls back to space-level ACL. Admins bypass group checks entirely (RLS still prevents cross-tenant access).

`assertSpaceAccess` — checks space permissions table for at least one matching group.

Both functions take the best access level across all matching group rows (`edit` beats `view`).

## apps/search

Standalone Express service on port 3002 (configurable). Separated from the API to allow independent scaling.

### Endpoints

- `GET /health`
- `GET /search?q=...&spaceId=...&type=...&authorId=...&tags=...&from=...&to=...&page=...&size=...` — full-text search with ACL filtering
- `GET /search/suggest?q=...` — title prefix autocomplete (max 5 results)

### SearchService (`src/searchService.ts`)

Builds an OpenSearch `bool` query:
- `must`: `multi_match` across `title^3`, `body`, `tags^2` with `fuzziness: AUTO`
- `filter`: org isolation + ACL filter (user's group IDs or direct user ID) + optional space/type/author/tags/date range filters
- `highlight`: title (1 fragment × 100 chars), body (3 fragments × 200 chars)
- Sort: `_score desc`, then `updated_at desc`

Auth in the search service uses JWT verification (HS256 via `JWT_SECRET`) and fetches group IDs from the DB on every request (no Redis in this service — can be added).

## apps/worker

Long-polling SQS consumer. Polls two queues concurrently with 20 s long-poll, 5-message batches, 300 s visibility timeout. Retries are implicit (message reappears after timeout on failure); after 3 failed attempts the DLQ receives the message.

### PdfProcessor (`src/pdfProcessor.ts`)

Triggered by `PDF_PROCESSING` messages:
1. Sets attachment `scanStatus = scanning`
2. Fetches file from quarantine S3 bucket
3. Validates PDF magic bytes (`%PDF` header check — basic malformed-file rejection)
4. Extracts text via `pdf-parse` (continues with empty body on extraction failure)
5. Copies file to served bucket with KMS encryption; deletes from quarantine
6. Sets `scanStatus = clean`, updates `s3Key`
7. Builds `SearchIndexDocument` (resolves ACL from space + document permissions) and indexes in OpenSearch

Files that fail the PDF check or throw are marked `scanStatus = error`.

### Indexer (`src/indexer.ts`)

Triggered by `SEARCH_INDEX` messages:
- `upsert` — fetches document from DB, resolves ACL group/user IDs, writes to OpenSearch index
- `delete` — removes document from OpenSearch by ID

### OpenSearch index (`src/opensearch.ts`)

Index: `wiki-documents`

| Field | Mapping |
|-------|---------|
| `org_id`, `document_id`, `space_id`, `type`, `tags`, `owner_id`, `acl_group_ids`, `acl_user_ids` | `keyword` |
| `title` | `text` (english analyzer) + `.keyword` sub-field |
| `body` | `text` (english analyzer) |
| `updated_at` | `date` |
| `content_embedding` | `knn_vector` (1536-dim, HNSW, cosine, Lucene engine) — **reserved null for Phase 2 AI search** |

`ensureIndex()` creates the index with this mapping on worker startup if it does not exist.

## apps/web

Next.js 15 App Router frontend.

### Pages

| Route | Component | Description |
|-------|-----------|-------------|
| `/` | `page.tsx` | Landing / redirect |
| `/spaces` | `SpacesList.tsx` | Grid of all accessible spaces (SWR-fetched) |
| `/spaces/[spaceId]` | `SpaceView.tsx` | Space detail + document list |
| `/spaces/[spaceId]/docs/[docId]` | `DocumentView.tsx` | Document editor or PDF viewer |
| `/search` | `SearchView.tsx` | Full-text search UI |

### Editor (`components/editor/RichTextEditor.tsx`)

Tiptap editor with:
- StarterKit (headings, bold, italic, lists, blockquote, horizontal rule)
- Placeholder
- Image embedding
- Link (click-to-open disabled; opens via toolbar)
- Resizable tables (Table + TableRow + TableCell + TableHeader)
- Syntax-highlighted code blocks via `CodeBlockLowlight` (lowlight, common language set)
- Auto-save: debounced 3 s after last keystroke, calls `onAutoSave` callback
- External content sync: `useEffect` pushes updated `content` prop into editor (e.g. version restore)

### PDF Viewer (`components/pdf/PdfViewer.tsx`)

Wraps `react-pdf` (`Document` + `Page` components).

### API client (`lib/api.ts`)

Typed fetch wrappers for all backend endpoints. Exports: `spacesApi`, `documentsApi`, `attachmentsApi`, `groupsApi`, `usersApi`, `searchApi`. Sends `credentials: include` on all requests.

## What is NOT yet implemented

The following areas were planned in the requirements but have no code yet:

- **Email delivery** — SES client is wired in the worker, `SES_FROM_ADDRESS` is in config, but no invite/notification emails are sent
- **Invite acceptance flow** — `invite_tokens` table exists; no endpoint to consume a token and activate a user
- **Document permissions UI** — API endpoints for document-level ACL exist; no frontend for it
- **Trash / restore UI** — `status = trashed` is set by `DELETE /documents/:id`; no restore endpoint or UI
- **Admin UI** — audit log and settings API endpoints exist; no frontend pages
- **Phase 2 AI search** — `content_embedding` field is in the index mapping (1536-dim knn_vector); no embedding generation or vector query
- **Cognito integration** — auth middleware supports Cognito RS256 JWTs; no user pool provisioning scripts or signup flow
- **Document tree navigation** — `parentId` is in the schema; no API or UI for hierarchy browsing
- **Audit log writes** — `audit_log` table exists; no middleware or service writes to it yet
